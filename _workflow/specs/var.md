# VAR｜新增變形

先讀 `_workflow/specs/_common.md`。

## 任務
為指定的演算法新增 `need` 個變形（variations）。每個變形都要是「在這個演算法的 Grasshopper C# 基礎範例上改某個部位」就能做出來的，而且和既有變形**不重複**。

## 步驟
1. 讀 `_workflow/index/<演算法>.json`：演算法原理（how_it_works）、全部既有變形（what_changes、how、result）、專案種子、曾被拒絕的變形。
2. **先分類既有變形**：依「改動部位」把每個既有變形歸到以下軸向，寫成 `coverage_note`（例如「維度 3、輸入 2、規則 4、輸出 2、混合 1、時間 0、分析 0」＋一句話說明缺什麼）：
   - `維度`：2D→3D、曲面上、體素、多層
   - `輸入`：影像、吸引點、邊界曲線、既有量體、地形、資料
   - `規則`：核心規則或參數的改變（權重、機率、鄰域、多物種…）
   - `輸出／製造`：管件、板材、雷切、3D 列印、繪圖機、組裝構件
   - `混合`：與其他演算法串接（寫出編號，例如「接 E03 Voronoi」）
   - `時間／動畫`：逐步生長、軌跡、互動
   - `分析／評估`：日照、結構、視域、效能指標回饋
3. **往缺的方向產出**，`need` 個變形要盡量分散在不同軸向、難度也要有高有低。
4. 逐一和既有變形比對：若改的是同一部位、結果看起來一樣，就換一個。

## 每個變形的欄位
```json
{
  "title": "短標題（6–16 字，可中英並列）",
  "level": 3,
  "what_changes": "改了哪個部位（規則／輸入／輸出／維度…）",
  "how": "具體要怎麼改 C#：用到哪些 RhinoCommon 型別或方法、加什麼輸入、改哪個迴圈",
  "result": "看起來或得到什麼結果（一句話，具體）",
  "axis": "維度｜輸入｜規則｜輸出／製造｜混合｜時間／動畫｜分析／評估",
  "nearest_existing": "最接近的既有變形（V03 標題）",
  "difference": "和它的差別（一句話）"
}
```
- 只有前五個欄位會進網站；`axis`、`nearest_existing`、`difference` 給審查用。
- `how` 要夠具體，學習者照著能改；不要寫「可以嘗試各種參數」這類空話。

## 輸出
`_workflow/stage/<RUN>/VAR_<演算法>.json`：
```json
{"unit": "VAR:<演算法>", "algo": "<演算法>", "coverage_note": "…", "items": [ … ]}
```

## 回報
一行：產出幾個變形、各屬哪個軸向。
